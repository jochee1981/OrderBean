## 📋 기능 요구사항 (Functional Requirements)

### 1. 주문 관리 기능 (Order Management)

#### 1.1 주문 생성 기능 (10개 테스트 실패)
- **우선순위**: 최우선
- **상태**: 완전 미구현

**세부 기능**:
1. **입력 검증**
   - 필수 필드 검증 (cafeId, items 배열)
   - items 배열이 비어있지 않은지 확인
   - menuId 유효성 검증 (존재하는 메뉴인지)
   - quantity 유효성 검증 (0 또는 음수 불가)
   - pickupTime 유효성 검증 (과거 시간 불가)

2. **가격 계산 로직**
   - 기본 메뉴 가격 계산
   - 선택된 옵션 가격 추가
   - 총액 계산 (totalAmount)
   - 할인 적용 (discountAmount)
   - 최종 금액 계산 (finalAmount)

3. **재고 확인 로직**
   - 메뉴 재고 확인
   - 주문 수량이 재고를 초과하는지 검증
   - 재고 부족 시 에러 코드 `OUT_OF_STOCK` 반환

4. **필수 옵션 검증**
   - 메뉴의 필수 옵션 그룹 확인
   - 필수 옵션이 선택되었는지 검증
   - 필수 옵션 미선택 시 에러 코드 `INVALID_OPTIONS` 반환

5. **주문 데이터 생성**
   - 주문 번호 생성 (고유 번호)
   - Order 레코드 생성
   - OrderItem 레코드 생성
   - OrderItemOption 레코드 생성
   - 주문 상태: `PENDING`으로 초기화

6. **응답 데이터**
   - orderId
   - orderNumber
   - status
   - totalAmount
   - finalAmount
   - items (주문 항목 목록)

#### 1.2 주문 재시도 기능
- **상태**: 미구현 (TODO 주석)
- **기능**: 실패한 주문 재시도 로직

#### 1.3 주문 조회 기능
- **상태**: 부분 구현 (DB 연결 문제로 테스트 실패)
- **기능**: 
  - 사용자별 주문 목록 조회 (`getOrders`)
  - 주문 상세 조회 (`getOrderById`)

#### 1.4 주문 취소 기능
- **상태**: 구현 완료 (테스트는 DB 연결 문제로 실패)
- **기능**: 주문 상태를 `CANCELLED`로 변경

### 2. 관리자 기능 (Admin Features)

#### 2.1 관리자 대시보드 (3개 테스트 실패)
- **우선순위**: 높음
- **상태**: 빈 구현 (빈 배열만 반환)

**세부 기능**:
1. **주문 상태별 조회**
   - `newOrders`: PENDING 상태 주문 목록
   - `preparingOrders`: PREPARING 상태 주문 목록
   - `readyOrders`: READY 상태 주문 목록

2. **권한 검증**
   - ADMIN 역할만 접근 가능
   - 비관리자 접근 시 403 에러

#### 2.2 주문 통계 분석 (Analytics)
- **상태**: 빈 구현 (모든 값이 0)
- **세부 기능**:
   - `totalOrders`: 전체 주문 수
   - `totalRevenue`: 총 매출액
   - `averagePrepTime`: 평균 준비 시간
   - `cancelRate`: 취소율
   - `popularMenus`: 인기 메뉴 목록 (판매량 기준)

#### 2.3 메뉴 분석 (Menu Analytics)
- **상태**: 빈 구현 (빈 배열 반환)
- **세부 기능**:
   - `menuSales`: 메뉴별 판매 통계
   - 메뉴별 판매량, 매출액 등

#### 2.4 주문 상태 업데이트
- **상태**: 구현 완료 (테스트는 DB 연결 문제로 실패)
- **기능**: 관리자가 주문 상태 변경 (WebSocket 알림 포함)

### 3. 인증 기능 (Authentication)

#### 3.1 회원가입 (Signup)
- **상태**: 구현 완료 (DB 연결 문제로 테스트 실패)
- **기능**: 
  - 이메일 중복 확인
  - 비밀번호 해싱
  - 사용자 생성
  - JWT 토큰 발급

#### 3.2 로그인 (Login)
- **상태**: 구현 완료 (DB 연결 문제로 테스트 실패)
- **기능**:

  - JWT 토큰 발급

- **기능**: 클라이언트 측 처리

- **상태**: 미구현 (빈 함수)
- **세부 기능**:
   - Refresh token 검증
   - 새로운 access token 발급
   - 응답에 새 토큰 포함

## 🔧 비기능 요구사항 (Non-Functional Requirements)

### 1. 테스트 환경 설정

#### 1.1 테스트 데이터베이스 설정
- **우선순위**: 최우선
- **문제**: `Can't reach database server at localhost:5432`
- **해결 방법**:
  1. 테스트용 PostgreSQL 데이터베이스 설정
  2. 또는 Prisma Mock 사용
  3. 또는 테스트 환경에서 DB 연결을 선택적으로 처리

#### 1.2 테스트 격리 (Test Isolation)
- **기능**: 각 테스트 후 데이터베이스 정리
- **목적**: 테스트 간 독립성 보장

#### 1.3 테스트 데이터 시드
- **기능**: 테스트용 기본 데이터 생성
- **필요 데이터**:
   - 테스트 사용자 (고객, 관리자)
   - 테스트 카페
   - 테스트 메뉴 및 옵션

---

### 2. 입력 검증 및 에러 처리

#### 2.1 입력 검증 스키마 (Zod)
- **우선순위**: 높음
- **적용 대상**:
   - 주문 생성 요청
   - 회원가입 요청
   - 로그인 요청
   - 기타 API 엔드포인트

#### 2.2 에러 코드 체계
- **필요한 에러 코드**:
   - `OUT_OF_STOCK`: 재고 부족
   - `INVALID_OPTIONS`: 필수 옵션 미선택
   - `INVALID_CREDENTIALS`: 인증 실패
   - `UNAUTHORIZED`: 인증 토큰 없음
   - `FORBIDDEN`: 권한 없음
   - `NOT_FOUND`: 리소스 없음
   - `VALIDATION_ERROR`: 입력 검증 실패

#### 2.3 에러 응답 형식
- **표준화된 에러 응답**:
   ```json
   {
     "success": false,
     "message": "에러 메시지",
     "code": "ERROR_CODE"
   }
   ```
